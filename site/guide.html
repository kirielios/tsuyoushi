Guide

Keiyoushi's extensions are Android APKs: outside Mihon they only run inside Suwayomi-Server, a JVM app you have to install and keep running. Tsuyoushi builds each one into a small JavaScript bundle instead, so a web reader loads it straight from a URL.

Getting started

The reader built for Tsuyoushi is NeetShelf. It runs in the browser on a computer, tablet or phone.

  1. Add the repo

    Open Settings → Extension repos and paste , or use Add to NeetShelf.

  2. Install sources

    Go to Browse → Extensions. Manga and anime have their own tabs.

  3. Install the helper

    Get the NeetShelf Helper for Chrome, Edge or Firefox (Orion on iPhone and iPad). Without it, manga still loads through a shared proxy, but anime does not.

Why a helper?

Manga and anime sites send no CORS headers, and many only answer when a request names them as the referrer. A plain browser tab can do neither, so the extensions run either on a JavaScript server, or in the browser with a helper extension that makes the requests for them.

Anime extensions return each video's URL together with the headers its host needs (Referer, Origin). The player has to send those with every request of that video, which is why anime needs the helper on your own device.

Troubleshooting

Extension list says my app is outdated, or it's empty

These bundles are for web readers. Mihon, TachiyomiSY and Komikku install APKs, so use Keiyoushi's own repo there. In NeetShelf, check the URL ends with index.json.

A source shows nothing, or "Cloudflare"

The site wants a browser check before it answers, so nothing can be loaded from it right now. It often clears on its own after a while; until then, another source is the way out.

Covers or pages don't show

Most image hosts only send images when the request names the site as the referrer. Install the helper, and make sure it's on for this site. Its Check page tells you whether headers get through.

An anime episode won't play

Videos need the helper (or NeetShelf Local Server / the Android app). If one server fails, pick another under Quality. Some files can't be seeked in every browser; another source usually works.

A source worked yesterday and broke today

Sites change their layout or domain. Update the extension under Browse → Extensions; if it's still broken, open an issue with the source name.

Requests

To request a new source or a fix, create an issue. The work is volunteer-based, so a request is not a promise. Some sites are impossible or too costly to keep working (Cloudflare challenges, sites that need to run their own JavaScript).

Using it in your own reader

index.json lists every source ("format": "mangareader-kei/1") with its bundle and icon paths. Anime extensions carry "kind": "anime".

{
  "id": "kei:en.mangapill:en",
  "pkg": "en.mangapill",
  "name": "MangaPill",
  "lang": "en",
  "baseUrl": "https://mangapill.com",
  "bundle": "en.mangapill/index.js",
  "icon": "en.mangapill/icon.png"
}

Each bundle is an IIFE that defines __tsuyoushi.create(host, meta), returning a source with Mihon's methods (getPopularManga, getLatestUpdates, getSearchManga, getPageList, …). Anime sources follow Aniyomi's contract and add getVideos(episode).

host is everything an extension gets from your reader: fetch (redirects, timeout, cookies), cheerio's load, a user agent and preferences. tools/node-host.ts is a complete Node.js host you can copy.

Contributing

Fork, port or fix an extension on a branch, then run the checks and open a pull request with the check output:

npm run generate -- en/mangapill   # meta.json + icon from upstream
npm run build
npm run check -- en.mangapill      # popular, latest, search, details, chapters, pages
npm run serve                      # http://localhost:4600/index.json

Disclaimer

Tsuyoushi hosts no manga or video. Each extension only tells a reader how to fetch a site's public pages, and runs on the reader's own device. Site owners or rights holders who want an extension removed can open an issue; it will be taken down.
